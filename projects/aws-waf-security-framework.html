The Problem

Global eCommerce platforms face a constant barrage of automated threats: credential stuffing bots, content scrapers, card-testing attacks, and inventory manipulation. While AWS WAF provides the building blocks for defense, configuring it correctly for eCommerce workloads requires deep knowledge of both attack patterns and Terraform best practices. Most publicly available WAF modules are generic and miss eCommerce-specific protections like checkout rate limiting and bot behavior challenges.

Quick Start

module "waf" {
  source      = "./modules/waf-regional"
  name_prefix = "production"

  enable_common_rules                = true
  enable_sql_injection_protection    = true
  enable_known_bad_inputs_protection = true
  enable_ip_reputation_protection    = true

  enable_rate_limiting = true
  rate_limit_threshold = 2000

  alb_arn = aws_lb.main.arn

  tags = {
    Environment = "production"
    ManagedBy   = "terraform"
  }
}

Key Learnings

  • WAF evaluation order matters -- IP reputation rules should run before application-layer rules to block known-bad sources early
  • Rate limiting must be tuned per-endpoint, not globally -- checkout flows have different thresholds than product pages
  • CloudFront and ALB WAF scopes (CLOUDFRONT vs REGIONAL) cannot share the same WebACL -- each requires its own
  • Soft-fail mode in CI (tfsec/Checkov) prevents false positives from blocking legitimate WAF configurations
  • WAF logging with block-only filters reduces CloudWatch costs by 80%+ while retaining security-relevant events
